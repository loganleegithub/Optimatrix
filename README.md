# Optimatrix · S2 公共行情与 Greeks.live 回测

本项目长期研究 Deribit BTC 币本位期权买方机会，目标是增加净 BTC 数量。当前保留 S1 真实公共行情，增加 Greeks.live 固定回测入口、本地运行记录和 BTC 计量说明。**没有获批策略，也没有真实资金授权。** 交易账户、交易模块和内部 Agent 均未接入；不提供下单按钮、真实余额或预设收益曲线。

回测结果可能不足以可靠重建 BTC 净收益。程序保留真实结果与缺口，不把服务返回成功、模型收益或一次实验当成可交易优势。当前实施情况与实际检查记录见 [S2 阶段记录](docs/stages/S2.md)；S1 基准证据见 [S1 阶段记录](docs/stages/S1.md)。

## 安装与启动（macOS）

需要 Python 3.12 或更新版本。在“终端”逐行执行：

```sh
cd /Users/logan/Optimatrix
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

第一次安装后，以后只需执行 `cd /Users/logan/Optimatrix` 和 `.venv/bin/python app.py`。这次实施已在本项目创建好 `.venv` 并安装依赖，无需再安装。

在浏览器打开 **[公共行情首页](http://127.0.0.1:8765)**，保留启动程序的终端。[回测页](http://127.0.0.1:8765/backtest)也可从首页右上角进入。只能从本机访问，未配置公网或开机自启。公共行情无需 Deribit 账户、API 密钥、`.env` 或 OpenAI API；缺少回测配置不会影响行情。仅回测后端读取 `.env` 中必要的 Greeks.live 配置，不要把凭据填进本项目网页或发到聊天中。

停止：在启动程序的终端按 **Ctrl+C**，等命令提示符重新出现。重新启动：再次执行 `.venv/bin/python app.py`。已打开的网页会自动恢复；也可刷新页面。

## 公共行情怎么看、怎样亲手检查

1. 确认顶端写着“公共行情只读”，交易账户和内部 Agent 均未接入；回测栏显示实际配置、能力检查及本地记录状态。CLI 登录只表示本机有登录状态，不代表内部 Agent 已接入或模型调用已验证。
2. 等待首批数据（正常网络通常数秒至十几秒）。指数是 USD/BTC；期权 bid/ask 是 BTC 权利金 / 1 BTC 标的；盘口数量是 BTC 标的数量。本阶段仅接受 `contract_size=1` 的 BTC 合约，所以数量在数值上也等于张数。
3. 比较交易所源时间、接收时间和数据年龄。等待约 20–40 秒，应看到采集轮次/时间推进；价格本身可能不变。期权使用订单簿 `timestamp`；指数接口没有独立事件时间，显示的是响应信封 `usOut`，不能当成指数事件时间。
4. 保留网页，在终端按 Ctrl+C。前台正常运行的浏览器通常在 3–7 秒内显示服务不可达，并保留上次值。浏览器后台节流/电脑休眠可能推迟检测；切回页面会立即重新验证。重新运行启动命令，观察页面恢复。
5. 可选：运行中暂时关闭网络。服务仍可达，但公共请求将失败；旧行情须标异常，年龄超过 60 秒标过时。恢复网络后等退避期结束再检查，可能需等待 30 秒到 5 分钟；交易所 `Retry-After` 更长时遵从它。

未取得数据是“未取得数据”，空订单簿是“无买盘/无卖盘”，两者都不是零价格。行情是间隔采集的快照，不保证点击时仍可成交，不是交易信号。

## 回测配置与操作

回测接入依据 [Greeks.live 回测网站](https://backtest.greeks.live/)当前网页使用的请求协议。**这是网页内部协议，不是已获稳定性承诺的公开回测 API。** 端点、返回字段和网页会话可能变化；本项目不承诺长期免维护或会话永不过期。

本轮仅使用人类授权复制到本地的现有网页回测会话。`.env.example` 列出了必要字段：`GREEKS_LIVE_AUTH_TOKEN` 接收完整的网页回测 `Authorization` 值。`GREEKS_LIVE_DATA_API_KEY` 是可选的 CSV Data API Key，**它与网页回测会话不同，不能自动互换**；本阶段不会用它发起数据接口或代替回测认证。

若没有 `.env`，按 `.env.example` 在项目根目录新建；已有文件只补充必要字段，不能覆盖其他配置。凭据由人类在本地填写或按已授权方式复制，不能贴进聊天、日志、样本或 Git。会话过期后，由人类在官方页面完成登录与续期，再更新本地字段；程序不自动登录、创建 API Key 或操作密钥管理流程，也不新增付费服务。配置“已齐备”仅表示检测到必要字段，不代表认证已通过。

1. 打开 [回测页](http://127.0.0.1:8765/backtest)，查看配置原因、固定实验、请求参数与假设。页面不显示密钥。
2. 点击“检查连接与服务能力”。等待检查结束，核对当前支持范围及未知项。启动程序、打开页面和刷新页面都不会自动提交回测。缺少配置、认证失败、限频或额外付费要求会显示原因，不以空结果代替成功。
3. 若尚无已提交记录且检查通过，点击“提交一次真实回测”。页面显示本地 `run_id`、提交与完成时间、服务任务标识、实际请求和状态。执行与行情采集分开，不阻塞行情页。
4. 本阶段只允许该固定实验一次远端提交。已有提交记录时按钮改为“查看已有固定回测”；重复点击、刷新或重启不会重新提交。提交结果不明时也不自动重发，以免重复消耗额度。
5. 在“已保存的运行记录”选择任务，核对结果币种、价格来源、费用假设与 BTC 缺口。停止程序后重新启动，再打开回测页，历史记录从本地读取，不靠再次调用服务重建。运行中停止造成的未完成记录会明确标为中断或结果未确认。

保持页面打开并按 Ctrl+C 停止程序，可检查“服务不可达”提示。页面保留上次读取的历史结果，但不再把运行状态标为已更新；重启后自动重新确认连接。若只有 Greeks.live 失败而本地服务仍在运行，页面应显示该检查或任务的失败原因，公共行情继续独立更新。

### 固定实验与 BTC 结果边界

本次实验是 `S2_BTC_LONG_CALL_V1`：2026-05-04 至 2026-05-05，09:00 UTC 时段，仅周一入场，买入 7D、0.5 Delta Call，采用 `reopen` 在下一有曲面数据日平仓；不对冲、不扫描参数。真实完整报告确认 `quantity=0.01` 为模型标的名义数量 0.01 BTC，不能当成权利金。`option_value` 已包含数量。理论 Delta/DTE 头寸没有实际挂牌合约标识，不按名称猜测。

价格来自 SABR/WV4 曲面模型估值，不是 bid/ask 成交回放，也不能称为可成交收益。费用参数固定为每腿每次开平仓标的名义额 1 bp，仅为本次实验假设，不是账户费率。请求明确采用 BTC 计量；不会混用 USDC 线性产品结算口径。S1 的少量实时行情快照不构成 H1 历史微观数据，本轮不运行 H1。

页面区分报价与名义数量、权利金支出、退出收入或到期结算、费用及 BTC 净盈亏。只有原始记录足以支持每个时点的币种、金额和费用口径，才能重建现金流；已包含费用时不能再次扣除，费用未知时不能当成零。USD 汇总盈亏不会被除以期末 BTC 价格冒充 BTC 策略收益。

权利金回报率以不含费用的模型开仓权利金为分母；假设账户回报率以明确标记的 0.2 BTC 初始资金为分母，二者不同。**0.2 BTC 不是真实账户余额。** 分子或分母证据不足就显示无法计算。没有逐笔记录，不能宣称完成逐笔核账；数据不足时明确显示“无法可靠重建 BTC 净收益”，同时保留服务报告值和精确缺口。

实际请求、完整原始响应、下载明细和运行状态保存在被 Git 忽略的 `local/backtests/`，其中每个运行目录以本地 `run_id` 命名。已验证的这次模型账本、金额及浮点尾差见 S2 阶段记录；实际成交收益仍未知。认证头不进入保存的请求，回测服务账户响应不落盘。不要上传整个本地目录；只有经过脱敏的小型样本和阶段检查记录准备提交 GitHub。

## 运行方式与常见问题

- 一个 Python 进程含一个行情采集线程与本地 Web 服务；公共行情浏览器每 3 秒只读取缓存。采集完成后等待 15 秒再开始下一轮；合约目录约每 5 分钟刷新。超时、HTTP 错误及 JSON-RPC 错误都保留旧值并显示失败；限频/连续失败逐步延长重试间隔。回测工作线程只在显式检查或提交操作后运行，没有独立常驻采集服务。
- 展示规则：按实时合约元数据过滤 BTC 币本位产品，选最近两个到期日，各选最靠近当前指数、同时存在 Call/Put 的行权价。优先离到期超过一小时的合约；没有时才选仍有效合约。每次目录更新重新选择，最多四个合约。这只是展示规则。
- `未取得数据` 一直不变：查看页面错误与 `logs/app.log`，检查网络是否能访问 `https://www.deribit.com`。公共行情客户端使用直接 HTTPS 并验证 TLS；不读取 `.netrc`、环境代理或密钥。不支持通过关闭证书验证绕过网络问题。
- 时间异常：确认 macOS 日期和时间正确。内部时间为 UTC，页面另显示台北时间（Asia/Taipei，UTC+8）。源时间异常或过时都不能被刷新页面消除。
- 同一项目只允许运行一个服务进程，操作系统文件锁阻止第二个进程改动运行中的历史记录，退出后自动释放；不要删除锁文件来绕过保护。
- `无法监听`：可能已启动，先打开现有页面，或在原终端停止服务。若 8765 被其他程序使用，可运行 `.venv/bin/python app.py --port 8766`，改用 <http://127.0.0.1:8766>。
- Codex CLI 未安装、未登录或检查失败不影响公共行情。服务启动时只调用 `codex --version` 和 `codex login status`，不打开登录文件、不运行任务；页面状态只代表该次启动检查。
- 回测显示“配置未齐备”：核对本地字段名；仅有 CSV Data API Key 不等于回测会话已配置。回测认证失效或协议变化需人类处理，反复刷新不能修复凭据，也不会重跑任务。
- 回测结果有数字但 BTC 净收益无法重建：查看价格来源、费用和逐笔记录缺口。这是数据口径限制，不应补零或猜测结算公式来消除提示。已提交任务结果未确认时，先保留本地记录，不删除记录以绕过一次提交保护。
- 本地日志自动轮转（最多约 3 MB），位于 `logs/`，不要上传。`.venv/`、`.env*`（示例除外）、日志、`local/`、Python 缓存均被 Git 忽略。

## 检查与文件

离线检查，无真实账户、无实时接口：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

若本机有 Node，可另运行前端离线检查：`node --test tests/frontend.test.cjs`。Node 不是启动网站的依赖。

S2 使用本机模拟服务做端到端检查，默认不读取真实 `.env`、不连接外网、不运行 CLI：

```sh
.venv/bin/python tests/s2_e2e.py
```

检查覆盖固定任务流程、失败与提交结果不明、重复提交保护、结果保存及重开、行情接口独立响应，以及 BTC 金额和费用口径。成功运行后产生可重复检查的 `local/s2-e2e/evidence.json`；它明确标为合成离线检查产物，不是回测研究结果。真实服务连通、调用与浏览器检查另记在 [S2 阶段记录](docs/stages/S2.md)，不由离线检查冒充。

显式进行一次真实公共连通检查并更新小型样本（访问四次公共接口）：

```sh
.venv/bin/python capture_sample.py
```

样本在 `docs/samples/deribit-public.json`，附 URL、UTC 接收时间及生产环境标志。合约列表保留两条原始记录并明确说明节选。Web 服务从不读取样本。阶段证据和限制见 [docs/stages/S1.md](docs/stages/S1.md)。

仅三个直接依赖：Flask（页面/API）、Waitress（本地 WSGI 服务）、Requests（公共行情与回测 HTTPS）。完整依赖及传递依赖精确版本在 `requirements.txt`。使用依据：[Flask 官方 Waitress 文档](https://flask.palletsprojects.com/en/stable/deploying/waitress/)、[Requests 超时说明](https://requests.readthedocs.io/en/stable/user/advanced/#timeouts)。
