## 已可操作的业务

- 首页是策略清单与待处理事项；可录入自然语言想法，或保存后批准研究员形成提案。保存想法不调用模型。
- 策略保存来源正文、取得状态、内容指纹、经济假设、产品与失败机制。来源链接本身不记为已查阅；当前没有自动抓取来源网页。
- 版本保存规则、实现状态和缺口。草案可编辑；首次验证冻结。冻结版本不能覆盖；子版本必须给出证据、原问题、实际改变、预期改善、可能损害及比较办法。
- 唯一可执行表达是现有单腿 BTC inverse 买方曲面实验：Call/Put、绝对 Delta、目标期限、数量、UTC 时段和入场星期。固定 reopen、无对冲、下一曲面观测日平仓。它不支持条件卖压、真实合约盘口、止损或权利金预算执行。
- 模型提案只是结构化草案。需要新算法时保留“待实现”及面向开发 Codex 的实施任务，不执行模型代码。模型实验描述不得夹带适配器不支持的交易条件；采纳时后端拒绝与实际规则不符的额外描述。
- 每次验证绑定策略版本、目的、实际请求、范围、价格性质、数量、费用、run_id、限制和引用。任务执行、数据核对与经济结论分别显示。
- 人类可保存保留、继续验证、修订、放弃或申请下一阶段的决定。工程/数据修复单独记录复核，不冒充规则进化。研究预算批准不是策略批准。
- 同账本费用压力产生验证记录，不产生策略版本、不创建远端任务。日期变化也属于验证条件。重复使用已见窗口必须标为研究段。
- 新旧版本只有日期、数量、费用、价格及计量条件匹配时才画对照；重叠样本不标为独立证据，也不自动排序优劣。

`strategies.py` 使用单进程锁与原子文件替换，把上述关系保存在 `local/strategies.json`。研究启动先保存批准意图，再保存任务与绑定，最后启动 runner。中断遗留任务只能按完全一致的批准上下文恢复；缺少归属则阻塞。刷新及重启不启动新任务。文件损坏时保留文件并禁止继续写入，原始研究和回测历史仍可访问。

新入口在 `/` 和 `/strategies`；`/operations` 汇总真实任务与数据入口。原 `/market`、`/backtest?run_id=...`、`/research?research_id=...` 保留。旧研究页的新建表单已改为策略入口，停止、恢复和证据查看保留；旧无归属新建 API 明确拒绝。
