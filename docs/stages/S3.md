## 调用链与修复记录

正式研究采用应用保存的 `research_id` 历史，每次 `codex exec` 是同一角色的下一步，不使用 `resume --last`，没有内部 Agent 团队。

| CLI 调用 | 真实动作 |
| --- | --- |
| 1 | researcher 自选四周窗口和买方参数，预先写假设/反例；预设 1 bp 与 5 bp 比较，提出新回测 |
| 2 | 请求读取首个 run；当时核账器仍标未核账，保留缺口 |
| 3 | 提出独立单次持仓核账对照，创建第二个真实任务 |
| 4 | 请求将第二个 run 的已核对原始记录改按 5 bp 计算费用 |
| 5 | 开始形成结论，开发者为修复实际核账缺陷显式停止；这次仍计预算 |
| 6 | 同一任务在原预算内显式恢复，读取更新后的两份核账与费用证据，输出最终中文结论 |

首个报告 `skip_total=7` 全部为请求规定的 `entry_weekday_filtered`，而 `missing_daily_observations=0`、未闭合 lot 为 0。旧校验把任何 skip 都视为缺失，导致误拒绝。已改为逐日核对预定星期过滤，并仅允许零头寸、零当日金额的完整空仓日；其他跳过与缺失仍拒绝。首 run 的 20 个闭合 lot、40 个事件、28 个日期现均核对；与服务汇总差 `1e-20 BTC`，在声明容差内。

修复后，普通程序重读已保存的原始文件，不 GET/POST；旧派生核账保留在 `analysis_history`。在任务已有 5 bp 请求的基础上，对各自同一账本确定性计算费用并注明来源，随后将更新字段交给调用 6。原始 CSV/报告、原始模型输出、旧输入和旧错误未覆写。

最终输出最初因“问题概括不等于逐字复述”被应用拒绝；其正文还含带引用的舍入百分比。修复过严校验后，应用始终用原问题展示，保存模型摘要；正文金额/百分比必须按所显示精度逐一匹配已引用的程序字段。不存在引用、无依据数字和无效结构仍不能成功。通过页面显式本地重校既有 `finish`，没有第七次正式模型调用、没有修改模型原文，原拒绝留在 `validation_history`。

模型指出 `fees_included=false` 与服务 PnL 已扣费用看似冲突：该旧字段实际描述输入的开仓/平仓价值是否已含费用，原始 `option_value` 未含费用；`audit.fees_already_in_reported_pnl=true` 描述服务报告净损益，二者口径不同。现增加明确 scope 说明，并在研究结论旁单列程序口径说明。金额计算始终只扣一次，没有为消除疑虑重算成更好收益。

探针 1 暴露了关闭 Code Mode host 后工具不可用的问题，不能作为权限通过证据；探针 2 修复后执行了真实受限 shell 检查并通过。两个探针均计入 2 次授权上限，正式研究前还补了正式 `agents.enabled=false` 开关。全部检查和失败记录保留本地。

## 实现与权限

- `research.py`：单任务管理器、持久化预算与动作、显式授权/停止/继续、证据 ID 与字段校验、结论绑定和本地重校。
- `researcher_cli.py`：固定参数的非交互子进程、stdin 文件输入、JSONL 事件、最终文件与结构独立校验；只管理自己的进程组。退出码 0 不单独代表成功。没有执行从模型 JSON 中提取的代码或 URL。
- `researcher/config.json`、`prompt.md`、`output.schema.json`：短固定 Prompt `btc-researcher-v1`，结构 `research-action-v1`，模型 `gpt-6-astra` / `high` / 标准速度（`service_tier=default`）。每任务保存快照和哈希。
- `backtest.py`：保留 S2 身份；九字段通用单腿买方入口；规范化实际请求与假设在 POST 前落盘。逻辑步骤幂等、内容复用显式标记。已知 ID 继续 GET；未知提交不重发；明确未发送的失败才可显式关联重试。
- `btc_accounting.py`：按 lot/leg 与事件链核对 open/mark/close、每日表、KPI、币种、费用；mark 不计现金。费用敏感性使用已核对数量与事件。未知形状、缺失或未闭合仍返回精确缺口。
- `app.py` 与 `static/`：简单研究页面、CSRF/同源保护、真实步骤和历史、关联回测、费用表、中文结论与程序说明。行情采集保持独立；网页请求不启动采集线程。

本机实际 CLI 为 `codex-cli 0.158.0-alpha.2.1`，`codex login status` 报告 ChatGPT 登录。`codex debug models` 当前模型目录明确列出 `gpt-6-astra` 和 `high`；未猜测 ID、未更新或降级 CLI。身份缓存没有被打印、复制或上传。

使用官方 named permissions profile：`:root=deny`、`:minimal=read`、本次准备目录只读、命令网络关闭，拒绝 tmp 的一般访问。CLI 忽略用户配置和规则，项目说明字节数为 0；关闭插件/MCP/浏览器/hooks/记忆/技能发现/子 Agent/goals，不继承应用的敏感环境变量。固定 Prompt 与输入是为本任务准备的内容，不是开发聊天记录。CLI 宿主认证通信保留，模型命令不能联网。

权限检查是本机实际沙盒，不是假结果：允许输入读取、禁止目录外读取、禁止符号链接越界、禁止内外写入；临时 loopback HTTP 服务在宿主前后请求均成功，沙盒请求失败。另以认证缓存所在目录中的临时假文件验证拒读，未触碰真实认证内容。没有改用户全局配置、没有关闭沙盒或使用 `--yolo`。

官方资料（实施时实际打开并对照本机帮助）：[非交互](https://learn.chatgpt.com/docs/non-interactive-mode)、[认证](https://learn.chatgpt.com/docs/auth)、[CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli)、[权限](https://learn.chatgpt.com/docs/permissions)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)、[Astra Prompt/AGENTS 建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。Greeks.live 字段依据仍为其[当前官方网页](https://backtest.greeks.live/static/)和公共 JS，以及实际认证后元数据、报告及 CSV；网页内部协议可能改变。
